# Проверка базы game_collection

Дата: 17 ноября 2026 года, московское время. Выполнение через SQL-редактор DBeaver 26.2.5 с административным подключением `postgres` к локальному PostgreSQL 18.7 на порту 5432.

## Применённые файлы

1. `00_create_database.sql` — успешно создана отдельная база UTF8 из template0. Первоначальная попытка создания через графический мастер DBeaver была отклонена самим клиентом из-за отключённого режима нескольких баз; SQL-команда создания выполнена успешно. Затем в DBeaver включено отображение всех баз данных.
2. `migrations/001_initial_schema.sql` — выполнено 25 операторов, собственная транзакция миграции завершена. Редактор был переключён на `public@game_collection`.
3. `tests/001_schema_checks.sql` — получено сообщение `PASS: 14 schema and data-integrity checks; test rows will be rolled back`. Скрипт завершился, выполнил ROLLBACK и вернул имя базы `game_collection`.
4. `01_inspect_database.sql` — проверены доступность пяти таблиц, представления и отсутствие тестовых строк после отката.

## Проверенные сценарии

- Статистика соответствует известной коллекции: 2 игры, 1 пройдена, 180 минут, средняя оценка 8, доля пройденных 50%.
- Статистика второго пользователя считается отдельно.
- Для пустой коллекции количества и время равны нулю, средняя оценка отсутствует.
- Email с теми же буквами в другом регистре отклоняется как повтор.
- Одна игра не добавляется одному пользователю дважды.
- Оценка 11, отрицательное время, неизвестный статус и будущая дата завершения отклоняются.
- Чужую ручную игру нельзя включить в коллекцию другого пользователя.
- SQL-обновление игрового времени через ON CONFLICT сохраняет оценку, статус, заметку и дату завершения.
- Смена статуса очищает дату завершения и отражается в статистике.
- Для пользователя запрещены две одновременно активные попытки импорта; после окончания первой новая разрешена.

Административное подключение использовалось для создания схемы; отдельную роль приложения предстоит настроить перед подключением Node.js.
